# Структура create-компонентов

- `wizard/` — оболочка мастера создания объявления и хост шагов.
  - `stepRegistry.js` — реестр шагов и компонентов. Динамическую связку шагов хранить здесь.
- `catalog/` — блоки страницы выбора категории в `/create`.
- `pages/` — page-level оболочки для create flow (`CreateAdPage`, `CreateCatalogPage`).
- `forms/steps/` — верхнеуровневые шаги мастера для авто-flow.
- `forms/parameters/` — формы параметров для конкретных flow.
- `forms/fields/` — низкоуровневые поля, переиспользуемые в шагах и формах.
- `completion/` — экраны после успешной отправки объявления.

## Правила

- Формы параметров должны оставаться тонкими: загрузка опций и бизнес-логика живут в `composables/create/useCreate*ParametersModel.js`.
- Page orchestration не должна утекать в форму.
- Если два flow отличаются только набором опций и текстами, лучше держать форму структурно одинаковой, а не разъезжаться по разметке без необходимости.

## Как раскладывать файлы

- Если компонент управляет только навигацией и состоянием мастера, он относится к `wizard/`.
- Если компонент рисует блок страницы выбора категории, он относится к `catalog/`.
- Если компонент — верхнеуровневый шаг формы, он относится к `forms/steps/`.
- Если компонент — форма параметров конкретного flow, он относится к `forms/parameters/`.
